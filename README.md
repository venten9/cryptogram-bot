## 🎯 Обзор и концепция игры

**«Шпион и Аналитик»** — это асимметричная кооперативная игра для двух участников. В отличие от традиционных текстовых игр или соло-головоломок, здесь **ни один игрок не обладает полнотой информации**:

- **Полевой Агент** видит зашифрованную радиограмму и интерактивный терминал дешифровки, но не знает открытого текста.
- **Штабной Аналитик** видит оригинальную депешу и частотный анализ букв, но не может сам нажимать кнопки подстановки в терминале Агента.

Победа достигается только благодаря постоянной командной координации: передаче разведывательных подсказок, запросам помощи SOS и последовательной проверке гипотез.

## 👥 Игровые роли и механики

### 1. Штабной Аналитик (Headquarters Analyst)
Игрок, создающий операцию через главное меню бота (`/start`).

* **Создание операции:**
  - **Выбор из каталога:** Доступ к библиотеке из 20 исторических и военных депеш (Юрий Гагарин, Александр Суворов, Михаил Кутузов, Рихард Зорге) с делением по категориям (`historical`, `military`, `intelligence`) и сложности (`EASY` 🟢, `MEDIUM` 🟡, `HARD` 🔴).
  - **Ввод собственной депеши:** FSM-диалог с валидацией (от 10 до 250 символов, русский язык, минимум 3 уникальные буквы, строгий запрет на латиницу).
* **Генерация инвайта:** Получение защищенной ссылки вида `https://t.me/<bot_username>?start=game_<invite_code>` с нативной кнопкой шаринга Telegram. Создатель не может подключиться к собственной игре в роли Агента.
* **Тактическое досье (HQ Dossier):**
  - Полный открытый текст депеши в моноширинном блоке `<pre>`.
  - Текущий статус операции (`Ожидание подключения`, `Операция в процессе`, `Депеша расшифрована`).
  - Позывной подключившегося Агента.
  - Метрики операции: раскрыто символов, ошибок Агента, использовано подсказок.
* **Инструменты поддержки:**
  - `💡 Раскрыть символ` — передача на терминал Агента разведданных по одному случайному неразгаданному символу.
  - `📊 Частоты букв` — отправка Агенту отдельной радиограммы с частотным распределением символов депеши в сопоставлении с эталоном русского языка (НКРЯ).
  - `🔄 Обновить табло` — принудительное обновление досье.
  - `❌ Отменить миссию` — отмена операции на этапе ожидания напарника.

### 2. Полевой Агент (Field Agent)
Второй игрок, подключающийся к миссии по ссылке-приглашению.

* **Подключение к миссии:** Переход по deep-link ссылке. Бот атомарно привязывает Агента к комнате и активирует экран терминала.
* **Полевой терминал дешифровки:**
  - Табло депеши: известные буквы отображаются открыто, неизвестные маскируются числовыми кодами (например, `[14]`, `[8]`). Знаки препинания и пробелы сохранены.
  - Индикатор прогресса: число разгаданных символов, процент завершения, счетчик ошибок.
* **Двухфазная клавиатура подстановки:**
  - **Фаза 1 (Сетка символов):** Компактная клавиатура из неразгаданных кодов `[1]`, `[2]`, ... с группировкой по 5 кнопок в ряду.
  - **Фаза 2 (Алфавитный пикер):** При выборе символа (например, `[14]`) открывается полная 32-буквенная клавиатура русского алфавита (4 ряда по 8 кнопок) и кнопка возврата `⬅️ Назад к символам`.
* **Результаты подстановки:**
  - **Верно (`CORRECT`):** Символ раскрывается во всем тексте, синхронно обновляются терминал Агента и досье Аналитика.
  - **Неверно (`WRONG`):** Терминал выводит всплывающий alert с предупреждением, счетчик ошибок инкрементируется.
* **Сигнал бедствия:**
  - Кнопка `📡 Запросить помощь Штаба` (SOS) — отправляет срочное оповещение Штабному Аналитику с просьбой передать подсказку.

## 🧮 Математика шифра и правила подстановки

1. **Нормализация текста:**
   - Все буквы переводятся в верхний регистр.
   - Буква `'Ё'` приводится к `'Е'` (алфавит нормализован до канонических 32 букв).
   - Пробелы, переводы строк, цифры и знаки препинания (`. , ! ? - — « » : ;`) не шифруются и сохраняют исходное форматирование.
2. **Биективная подстановка:**
   - Каждой уникальной букве нормализованного текста ставится во взаимно-однозначное соответствие уникальный числовой идентификатор $c \in \{1, \dots, K\}$, где $K$ — количество уникальных букв.
   - Коллизии математически исключены ($|\text{Unique}(Letters)| = |\text{Unique}(Codes)|$).
3. **Условие победы:**
   - Победа фиксируется строго тогда, когда множество раскрытых Агентом букв $R$ покрывает все уникальные буквы текста $U$ ($U \subseteq R$).

```
└──────────────┬──────────────────────────────┬───────────────┘
               │                              │
┌──────────────▼──────────────┐┌──────────────▼───────────────┐

```

### Отказоустойчивость и безопасность

- **Защита от состояния гонки (Concurrency Locking):**  
  Класс `SessionLockManager` предоставляет асинхронный контекстный менеджер на базе `asyncio.Lock` с подсчетом ссылок (`ref_count`). Любые параллельные действия обоих игроков в одной комнате (одновременные догадки, отправка подсказки, запрос SOS) строго сериализуются, исключая потерю обновлений в базе данных.
- **Безопасность лимита CallbackData (< 40 байт):**  
  Telegram Bot API накладывает жесткий лимит в **64 байта** на `callback_data`. В боте используются сжатые строковые схемы и 8-значные hex-токены комнат:
  - `sym:a1b2c3d4:14` (15 байт)
  - `guess:a1b2c3d4:14:А` (20 байт)
  - `hint:a1b2c3d4:reveal:0` (22 байта)  
  Худший случай во всей системе не превышает **32 байт** (запас надежности >= 50%).
- **Щит от ошибок редактирования (`TelegramBadRequest`):**  
  Повторные или дублирующие клики по инлайн-кнопкам вызывают исключение `message is not modified`. Функции `safe_edit_message`, `safe_edit_callback` и глобальный фильтр `errors_router` перехватывают эти ошибки без падения приложения.
- **Экранирование HTML:**  
  Весь пользовательский ввод и системные тексты экранируются с помощью `html.escape` перед оборачиванием в теги `<pre>` и `<code>`, что предотвращает поломку HTML-парсера Telegram.
- **Разделение прав доступа (RBAC):**  
  Действия строго валидируются на стороне сервера. Попытка Агента отправить подсказку или попытка Аналитика разгадать символ немедленно блокируются с вызовом `UnauthorizedActionError`.

## 💻 Установка и настройка

### Требования к окружению
- **Python:** версия **3.14+** (поддерживается работа на Python 3.11, 3.12, 3.13, 3.14).
- **SQLite:** версия 3.35+ (входит в стандартную поставку Python).
- **Платформа:** Windows 10/11, Ubuntu/Debian Linux, macOS.

### Пошаговая установка

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/your-username/spy-analyst-cryptogram.git
   cd spy-analyst-cryptogram
   ```

2. **Создайте и активируйте виртуальное окружение:**
   - **Windows (PowerShell):**
     ```powershell
     py -3.14 -m venv .venv
     .venv\Scripts\Activate.ps1
     ```
   - **Linux / macOS (Bash):**
     ```bash
     python3.14 -m venv .venv
     source .venv/bin/activate
     ```

3. **Обновите pip и установите зависимости:**
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

### Конфигурация окружения (.env)

Создайте файл `.env` в корневом каталоге проекта на основе предоставленного шаблона:

```bash
cp .env.example .env
```

Параметры конфигурации:

| Переменная | Обязательная | По умолчанию | Описание |
|---|:---:|---|---|
| `BOT_TOKEN` | Да (для продакшна) | `""` (пустая строка) | Токен бота от [@BotFather](https://t.me/BotFather). При пустом значении бот не подключается к сети, но работают локальные тесты и CLI-симуляция. |
| `DB_PATH` | Нет | `sqlite+aiosqlite:///cryptogram.db` | URI подключения к базе данных SQLite через драйвер aiosqlite. |
| `BOT_USERNAME` | Нет | `SpyAnalystBot` | Юзернейм бота (без символа `@`), используемый при формировании ссылок-приглашений. |
| `DEBUG` | Нет | `False` | Режим расширенного логирования SQL-запросов и событий Aiogram. |

Пример содержимого `.env`:
```ini
BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz_SAMPLE
DB_PATH=sqlite+aiosqlite:///cryptogram.db
BOT_USERNAME=SpyAnalystBot
DEBUG=False
```

## 🚀 Запуск приложения

### Запуск Telegram-бота

Для запуска бота в режиме Long Polling выполните:

- **Windows:**
  ```powershell
  py -m bot.app
  ```
- **Linux / macOS:**
  ```bash
  python -m bot.app
  ```

При старте приложение автоматически:
1. Загрузит переменные окружения и проверит валидность `BOT_TOKEN`.
2. Подключит асинхронный движок SQLite и применит оптимизационные PRAGMA-настройки (WAL mode, busy_timeout=5000).
3. Создаст все необходимые таблицы базы данных (`users`, `game_sessions`, `hint_logs`), если они еще не существуют.
4. Запустит прием входящих обновлений от Telegram API.

### Автономная CLI-симуляция (без Telegram)

Для демонстрации игрового процесса, отладки и прохождения игры без регистрации реального бота в Telegram предусмотрен автономный консольный симулятор:

```bash
# Интерактивная игра двух игроков прямо в терминале
py -m scripts.simulate_game --interactive

# Автоматический сквозной прогон случайной депеши из каталога
py -m scripts.simulate_game --auto
```

Симулятор использует встроенную инфраструктуру `MockTelegramSession` и `MockPlayerClient`, напрямую подавая синтетические события `Update` в диспетчер Aiogram 3.x.

## 🧪 Тестирование и верификация

Проект снабжен многоуровневым набором автоматических тестов на базе **pytest** и **pytest-asyncio** (более **225 тестов**), гарантирующим математическую корректность шифрования, целостность транзакций базы данных и отказоустойчивость интерфейса.

### Запуск полного набора тестов
```bash
py -m pytest -v
```

### Запуск по уровням (ярусам)

* **Tier 1 — Математические инварианты движка (чистая логика без I/O):**
  ```bash
  py -m pytest tests/test_engine_unit.py -v -m unit
  ```
  *Проверяет:* нормализацию 'Ё'->'Е', биективность шифра, детерминизм сидов, формулу частот, теоретико-множественную победу.

* **Tier 2 — Граничные условия и патологические входные данные:**
  ```bash
  py -m pytest tests/test_engine_boundary.py -v -m boundary
  ```
  *Проверяет:* панграммы со всеми 32 буквами алфавита, редкие буквы ('Ъ', 'Э', 'Щ'), эмодзи, кавычки, переводы строк, пустые строки.

* **Tier 3 — Асинхронная БД, транзакции и состояние гонки:**
  ```bash
  py -m pytest tests/test_database_async.py tests/test_adversarial_concurrency.py -v
  ```
  *Проверяет:* создание таблиц, SQLite WAL-режим, 64-битные Telegram ID, каскадные удаления, параллельные клики (`asyncio.gather`), защиту от гонок мьютексами.

* **Tier 4 — Интеграционное тестирование Aiogram UI и симуляция:**
  ```bash
  py -m pytest tests/test_bot_mock.py tests/test_adversarial_m3_callbacks.py -v
  ```
  *Проверяет:* полную цепочку от `/start` до финала победы, роутинг deep-link, 32-кнопочный пикер алфавита, перехват `TelegramBadRequest`, лимиты размера колбэков.

* **Стресс-тестирование и фаззинг:**
  ```bash
  py -m pytest tests/test_adversarial_m3_stress.py tests/test_adversarial_fuzz.py -v
  ```
